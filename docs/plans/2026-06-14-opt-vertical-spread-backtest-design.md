# ETF 期权垂直价差回测 — 设计文档

- 日期：2026-06-14
- 作者：jinwq（与 AI 协作）
- 状态：已确认，待生成实施计划
- 数据源：`stock_tushare.opt_basic`、`stock_tushare.opt_daily`、`stock_tushare.etf_daily`

## 1. 背景与目标

日常实盘以**垂直价差**为主：看多用**认购牛市价差**（买低行权价 Call + 卖高行权价 Call），看空用**认沽熊市价差**（买高行权价 Put + 卖低行权价 Put）。交易品种限 **510300.SH、510500.SH、588000.SH、159915.SZ** 四个 ETF 期权。

用历史数据回测，给出**有数据支撑**的两个结论：

- **问题一（成本与止盈）**：建仓时初始净借记成本落在什么区间性价比最好？价差扩大到多少倍平仓获利了结性价比最高？
- **问题二（到期月）**：当月 / 下月 / 当季 / 下季合约应如何选择？

## 2. 数据现状（已核验）

| 项 | 结论 |
|---|---|
| `opt_daily` 跨度 | 2015-02-09 ~ 2026-06-12，约 2009 万行 |
| `opt_daily` 可用字段 | `open/high/low/close`、`settle`、`pre_settle`、`vol`、`oi`、`amount` |
| **缺失** | 无 IV、无 Greeks、无标的价（→ 用 moneyness 替代 delta，标的价取 `etf_daily`） |
| `opt_basic` 关键字段 | `opt_code`(如 OP510300.SH)、`call_put`(C/P)、`exercise_price`、`maturity_date`、`s_month`(YYYYMM)、`list_date`、`delist_date` |
| 四标的期权起始 | 510300=2019-12、159915/510500=2022-09、588000=2023-06，均到 2026-06 |
| `etf_daily` | 含 `close_qfq`(前复权) 与 `ma10/ma20/ma60`、`bias*`，方向信号与"事后涨跌判定"现成可用 |
| 标的↔期权关联 | `opt_basic.opt_code = 'OP' + ETF代码`（如 510300.SH → OP510300.SH） |

## 3. 已确认的关键决策

1. **方案 C**：条件回测（A）为主结论 + 均线信号回测（B）做真实盈亏佐证。
2. **成交价口径**：用 `opt_daily.close` 建/平仓 + 固定滑点；`settle` 仅作敏感性复核（非主结论）。
3. **样本范围**：每个标的从各自期权上市日起，样本最大化（不强制对齐起点）。

## 4. 策略与口径定义

### 4.1 价差结构
- 牛市认购价差（看多）：买低 K Call + 卖高 K Call，净借记 = Call(K低) − Call(K高)。
- 熊市认沽价差（看空）：买高 K Put + 卖低 K Put，净借记 = Put(K高) − Put(K低)。

### 4.2 选腿（无 Greeks，用 moneyness）
- 当日同 `opt_code`+`call_put`+`maturity_date` 的在交易合约，按 `exercise_price` 升序构成"行权价阶梯"，相邻为 **1 档**。
- 买腿 = 最接近平值（|K − S| 最小，S = 当日 `etf_daily.close_qfq` 对应的实际收盘 `close`）。
- 卖腿 = 自买腿沿价外方向移 **W 档**（W = 价差宽度，扫描 1/2/3 档）。
- 两腿必须同一 `maturity_date`、同 `call_put`、当日均有行情。

### 4.3 到期月分类（问题二）
在每个建仓交易日 t，对该标的所有"未到期且在交易"的合约取 `maturity_date` 升序去重：
- **当月** = 第 1 个到期日；**下月** = 第 2 个到期日。
- **当季** = 月份 ∈ {3,6,9,12} 中最近的到期日；**下季** = 次近的季月到期日。
- 注意重叠：当月本身可能就是季月（如 6 月），此时当月=当季，回测中按"四类各自独立取合约"，允许样本重叠，报告中标注。

### 4.4 成交与成本
- 合约单位 `per_unit` = 10000（ETF 期权），最小变动 0.0001 元。
- 滑点：每腿每次成交 1 个最小变动价位（买腿付 close+tick，卖腿收 close−tick），可配置档数。
- 手续费：默认每腿每张固定 `FEE_PER_LEG` 元（默认值待定，可设 2 元/张），可配置为 0。
- 单笔盈亏 = (平仓净价差 − 建仓净借记) × per_unit − 往返滑点 − 手续费。

## 5. 入场 / 出场规则

### 5.1 入场
- 方案 A（条件回测）：在每个交易日（默认按**周一采样**降低重叠与自相关，可切日频）建仓，四到期月 × 价差宽度 1/2/3 档全组合。
- 方案 B（信号回测）：标的 `close` 上穿 `ma20` 触发牛市认购价差；下穿触发熊市认沽价差。

### 5.2 出场（网格扫描 — 对应问题一"平仓点"）
- 止盈：价差现值 ≥ 建仓净借记 × 倍数 K，K ∈ {1.3, 1.5, 1.8, 2.0, 2.5}。
- 止损（可选）：价差现值 ≤ 建仓净借记 × 0.5。
- 时间止损：到期前固定 D 天或最后交易日强制平仓（默认到期前 1 个交易日）。
- 每日盘后用 close 检查触发，次日或当日收盘平（默认当日 close 平，止盈用线性近似）。

### 5.3 流动性过滤
- 建仓日两腿 `vol` > 0 且 `oi` ≥ `MIN_OI`（默认 50，可配置），否则跳过该组合并计入"不可成交"。

## 6. 评价指标

按 (标的 × 到期月类别 × 价差宽度 × 止盈倍数 K) 网格统计：

- 样本数、可成交率
- 胜率、平均收益率（对建仓净借记的 %）、盈亏比
- **期望收益 / 平均持有天数**（时间效率，性价比主指标）
- 最大回撤、最大单笔亏损
- 初始成本相对值分布（净借记 ÷ 最大价差宽度）→ 回答问题一的"成本区间"

条件回测 A 额外：在"标的于持有期内确实上涨（牛市）/下跌（熊市）"的子样本上评估，回答"**方向判断正确时**的最优参数"。

## 7. 输出

- 单文件脚本 `opt_vertical_spread_backtest.py`（camelCase、同名日志 `opt_vertical_spread_backtest.log`、可中断、Windows 安全日志轮转）。
- CSV 网格结果（落 `docs/` 或脚本同目录 `out/`）+ 控制台结论摘要。
- 结论三段：① 推荐初始成本区间；② 推荐止盈倍数；③ 推荐到期月。

## 8. 范围与取舍（YAGNI）

- 不引入 IV / Greeks（库内无）。
- 不做日内、不做滚动调仓 / 移仓。
- 不做组合层资金管理（单笔独立评估为主，方案 B 给净值曲线）。
- 默认 4 个标的全测；并行按"标的 × 到期月类别"独立任务，可用线程池（纯本地读，注意 MySQL 连接每线程独立）。
